# 滑雪板保养排期台（hxyfront-62004）

保养旺季的前台排期工具：接单核价、按师傅/蜡锅/工位排期、交板参数把关，
替代白板手工分配，避免两张撞档的雪板排给同一位师傅或同一只蜡锅。

## 业务规则

- 接单记录：客户、电话、雪板品牌、长度、板型、保养项目；蜡型随项目确定
  （低温蜡 / 全温蜡 / 热蜡）；取板时间与指定师傅在排期台录入。
- 同一日期时段内，一位师傅只承接一张板，一只蜡锅也只服务一张板。
- 蜡型与工位、蜡锅温区不合（如热蜡排入低温区）直接拦住，**原排期不动**。
- 顾客改板型或保养项目后，原报价立即失效、师傅/工位/蜡锅占用释放，
  工单退回待核价，由前台重新核价。
- 交板前必须录入侧刃、底刃、打蜡温度；含底板修补的工单还必须录入修补结果，
  否则挡住无法完工。已完工记录只读。

## 三层分开维护

| 层 | 目录 | 职责 |
| --- | --- | --- |
| 排期规则 | `src/domain/` | 类型模型、服务目录与报价、冲突/温区/交板校验等纯函数 |
| 本地资料存取 | `src/data/storage.ts` | localStorage 读写、版本控制、种子数据、重置 |
| 操作页 | `src/components/`、`src/App.tsx` | 接单核价、排期台、交板录入、工单总览 |

改规则只动 `domain`，改存储只动 `data`，改页面只动 `components`。

## 本地运行

```bash
npm install
npm run dev      # http://localhost:62004
npm run build    # 类型检查 + 生产构建
```

所有数据保存在浏览器 `localStorage`（键：`ski-shop-schedule-v1`），
页面顶部「重置演示数据」可恢复内置示例（含当天已排期的工单，便于验证撞档拦截）。

技术栈：React 19 + Vite + TypeScript
