# 雪板保养排期台

面向滑雪板调校店的保养旺季排期系统，替代白板分档，解决「两张撞档雪板排给同一师傅」的问题。

## 业务流程

1. **接单**：记录客户、雪板品牌与长度、板型、保养项目（刃部调校 / 打蜡 / 底板修补）、取板时间、指定师傅；含打蜡时必须选 **低温蜡 / 全温蜡 / 热蜡**。保存后自动试算报价。
2. **核价**：前台确认报价后工单进入待排期。顾客改板型或项目（含蜡型）后，**原报价失效、原师傅 / 蜡锅 / 工位占用同步释放**，需重新核价。
3. **排期**：按「上午 / 下午 / 晚间」三档分配师傅与蜡锅。规则：
   - 同一时段，一位师傅只能承接一张板；
   - 同一时段，一只蜡锅只能服务一张板；
   - 蜡型必须与工位温区一致（低温蜡→低温区、全温蜡→全温区、热蜡→高温区），不合直接拦截，**原排期保持不动**；
   - 不含打蜡的项目不占用蜡锅。
4. **交板**：必须录入侧刃角度、底刃角度、打蜡温度；含底板修补时还必须录入修补结果，否则挡住。
5. **完工记录只读**：完成后只能查看，不能再编辑。

## 架构（三层分开维护）

- `src/rules/` — **排期规则层**。`masterData.ts` 维护师傅 / 工位温区 / 蜡锅 / 时段 / 项目 / 价格 / 蜡型温区对照；`scheduling.ts` 是纯函数：报价、冲突校验、温区拦截、改单失效、完工门槛。不含任何 UI 代码。
- `src/storage/` — **本地资料存取层**。`localStore.ts` 负责 localStorage 读写与重置，`seed.ts` 为首访演示数据，`dates.ts` 为日期工具。
- `src/pages/` — **操作页**。`SchedulingDesk.tsx` 排期看板与工单总览，`IntakeForm/IntakeDialog` 接单，`ScheduleDialog` 排期，`ReviseDialog` 顾客改单，`CompletionDialog` 交板录入，`OrderDetail` 只读详情。
- `src/state/useOrders.ts` — 串联规则与存取的状态钩子，页面不直接碰 localStorage。

## 本地运行

```bash
npm install
npm run dev
```

开发端口：62004。数据保存在浏览器 localStorage（键名 `ski-bench:orders:v1`），可通过页面右上角「重置演示数据」恢复初始数据。
